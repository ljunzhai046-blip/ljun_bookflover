
**引入：为什么需要按键**

前两次实验中，单片机一直在“自说自话”：第一次按固定节奏闪灯，第二次通过串口和电脑聊天。但有一

个问题：如果我想在程序运行过程中告诉单片机“现在切换个模式”“现在停一下”，怎么办？总不能每次都

改代码重新烧录。

按键就是单片机的“触觉”。有了它，人可以直接和单片机交互：按一下切换档位、按一下启停设备。这是

几乎所有电子产品的标配——遥控器、洗衣机、电梯按钮，背后都是按键输入。

本次实验我们让单片机学会“感觉”：按一下按键，LED 翻转，同时串口打印一条消息。

**先分清两种方式：轮询和中断:**

一句话记住：轮询是“我一直问”，中断是“有事你叫我”。本次两种都学：先写轮询体会它的笨拙，再写中断感受它的优雅。


==🟡**第一步：轻量原理 —— 三句话看懂按键与中断**==

一、上拉电阻是什么

按键的接法很简单：一脚接 PA0，另一脚接 GND。问题是：按键没按下时，PA0 处于悬空状态（谁也不接），电平高低不定，像一根“天线”一样乱飘，单片机可能误判。

上拉电阻就是一根把 PA0 轻轻“拽”到高电平的橡皮筋：按键没按时，PA0 稳定在高电平；按键按下时，PA0直接接通 GND，变成确定的低电平。

STM32 内部自带上拉电阻，CubeMX 里勾选 Pull-up 即可，不需要外接任何元件。

记结论：本次按键“没按 = 高电平，按下 = 低电平”。

**二、外部中断（EXTI）是什么**

EXTI（External Interrupt，外部中断）是 STM32 里专门监视引脚电平变化的功能模块。


配置好之后，当 PA0 的电平从“高变低”的瞬间（也就是按键按下的瞬间），硬件会自动暂停主程序，转去

执行一段我们写好的函数（回调函数），执行完再回来接着干原来的活。

电平“高变低”叫下降沿，“低变高”叫上升沿。我们的按键按下是下降沿，所以本次选下降沿触发。

**三、按键抖动是什么（了解即可）**

机械按键内部是金属弹片，按下和松开的瞬间，触点会快速通断好几次——几毫秒内电平像“弹跳”一样反复抖动，而不是干净利落的一次变化。

后果：按一下，单片机可能以为按了五六下。解决办法叫消抖：检测到变化后，短时间（比如 50ms）内的重复变化直接忽略。本次两个实验分别用两种消抖方法，下面会讲。

**==🟡第三步：实验一 —— 轮询方式读按键（先体会“笨办法”）==**

一、添加代码

打开 Core/Src/main.c，在 while(1) 循环里（/* USER CODE END WHILE */ 与 /* USER CODE BEGIN 3

*/ 之间）写入：

printf("main loop running... %d\r\n", count++);

HAL_Delay(1000);

if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) // PA0 为低电平，说明按键按下

{

HAL_Delay(20); // 延时 20ms 消抖

if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) // 再确认一次，确实按

{

HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_4); // LED 翻转

printf("button pressed (polling), LED toggled\r\n");

while (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET); // 等按键松开

}

}

（count 变量第二次已经定义过，直接用即可；如果没有，在 /* USER CODE BEGIN PV */ 区域添加 uint16_t count = 0;）

代码说明：

• HAL_GPIO_ReadPin：读取引脚电平，返回 SET（高电平）或 RESET（低电平）。

• 为什么要读两次：第一次读到低电平可能只是抖动，延时 20ms 后再确认，两次都是低电平才算真的

按下。这就是轮询方式的消抖。

• 最后那句 while 是“等松手”：不加它，按住不放会被当成按了很多次。

**三、验证结果**

打开 Serial Monitor（选好 COM 口、波特率 115200，Start Monitoring），可以看到每秒打印一行 main loop running…。

重点体会：轻轻点一下按键，很可能没反应；按住大约 1 秒左右，才会看到 LED 翻转、串口打印 button pressed (polling)…。
为什么这么“迟钝”？因为主循环里有 HAL_Delay(1000)，这 1 秒里单片机“睡死”了，根本不看按键，只有醒来的一瞬间才瞟一眼。这就是轮询的缺点：CPU 被别的事占住时，按键就会被怠慢。


**==🟡第四步：实验二 —— 中断方式，随按随响应**==

一、添加代码

① 定义消抖用的时间戳变量：在 /* USER CODE BEGIN PV */ 区域添加：

uint32_t last_press_tick = 0; // 上一次有效触发的时间戳（毫秒）

② 编写中断回调函数：在 /* USER CODE BEGIN 4 */ 区域添加：

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)

{

if (GPIO_Pin == GPIO_PIN_0) // 确认是 PA0 触发的

{

uint32_t now = HAL_GetTick(); // 当前系统运行的毫秒数

if (now - last_press_tick < 50) // 距上次触发不到 50ms，视为抖动，忽略

{

return;

}

last_press_tick = now; // 记录本次有效触发时间

HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_4); // LED 翻转

printf("button pressed (interrupt), LED toggled\r\n");

}

}

代码说明：

• 和第二次串口的 HAL_UART_RxCpltCallback 一样，HAL_GPIO_EXTI_Callback 也是 HAL 库约定好

的函数名，引脚电平一变，HAL 库会自动调用它。函数名不能改，原样复制即可。

• 这里的消抖不用 HAL_Delay，改用“时间戳对比”：HAL_GetTick() 返回系统运行的毫秒数，50ms 内

的重复触发直接 return 掉。

• 重要规矩：中断回调函数里禁止写 HAL_Delay！ 中断里 SysTick 计时可能停摆，会导致整个程序卡

死。中断里只做“短平快”的事，需要时间判断就用时间戳法。

• 主循环里的代码（每秒打印 running…）保持不动，一行都不用改。

二、编译烧录，验证结果

编译烧录，接线不变。Serial Monitor 里主循环依然每秒打印 running…，但现在：轻轻点一下按键，立刻有反应——LED 翻转、串口打印，不用按住傻等。

这就是中断的优雅之处：主循环该打印打印，按键事件“随叫随到”，互不耽误。和实验一对比一下，感受非常直观。

进阶提示：在中断里直接 printf 其实不算好习惯（发送是阻塞的，数据量大时会拖慢系统）。正式项目的

做法是：中断里只置一个标志位，主循环检测到标志位后再 printf。本次数据量极小，先这样用，知道有这回事即可。
