
# **1 先看懂：蓝牙模块就是一根无线串口线**

HC-05 把手机发来的字节原样送到 STM32 的 USART2；STM32 发回去的字节，也会被原样送回手机。你不需要写蓝牙协议栈，只要会 UART 收发。

最终效果：手机发 PING 收到 PONG；发 LED ON / LED OFF 控制板载 LED；发 STATUS 查看状态。数据路径是：手机 → 蓝牙 → HC-05 → USART2 → STM32 → 原路返回。

**2.** 确认 HC-05 的 TXD 接 PA3，RXD 接 PA2，没有接反。

**3.** 确认模块 VCC 电压与丝印一致，5V 没有接到 3.3V 引脚。

# **3****代码：中断收字节，主循环拼命令**

中断只做一件事：把收到的 1 个字节放进环形缓冲区，然后马上退出。主循环从缓冲区取字节，遇到换行符就拼成一条命令，再比较字符串、点灯、回复。这样既不会丢数据，也不会让中断执行太久。

|   |
|---|
|**环形缓冲区怎么理解**<br><br>中断写 head，主循环读 tail；head == tail 为空。缓冲区 256 字节，9600 波特率下够用。|

在 Core/Inc 新建 bluetooth.h，在 Core/Src 新建 bluetooth.c。CubeMX 的 CMake 工程通常会自动收集 Core/Src 下的源文件；如果编译找不到，执行一次 CMake: Configure。

**代码 4-1  bluetooth.h**

#ifndef BLUETOOTH_H

#define BLUETOOTH_H

#include <stdint.h>

void Bluetooth_Init(void);

void Bluetooth_Send(const uint8_t *data, uint16_t len);

void Bluetooth_SendString(const char *text);

int  Bluetooth_ReadByte(uint8_t *data);

uint32_t Bluetooth_GetDropped(void);

#endif

**代码 4-2  bluetooth.c**

#include "bluetooth.h"

#include "main.h"

#include <string.h>

#define RX_SIZE 256U

static uint8_t rx_byte;

static uint8_t rx_buf[RX_SIZE];

static volatile uint16_t head, tail;

static volatile uint32_t dropped;

void Bluetooth_Init(void)

{

    head = tail = dropped = 0;

    HAL_UART_Receive_IT(&huart2, &rx_byte, 1);

}

void Bluetooth_Send(const uint8_t *data, uint16_t len)

{

    if ((data != NULL) && (len > 0U)) {

        HAL_UART_Transmit(&huart2, data, len, 1000);

    }

}

void Bluetooth_SendString(const char *text)

{

    if (text != NULL) {

        Bluetooth_Send((const uint8_t *)text, (uint16_t)strlen(text));

    }

}

int Bluetooth_ReadByte(uint8_t *data)

{

    if ((data == NULL) || (tail == head)) return 0;

    *data = rx_buf[tail];

    tail = (uint16_t)((tail + 1U) % RX_SIZE);

    return 1;

}

uint32_t Bluetooth_GetDropped(void) { return dropped; }

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)

{

    if (huart->Instance == USART2) {

        uint16_t next = (uint16_t)((head + 1U) % RX_SIZE);

        if (next != tail) { rx_buf[head] = rx_byte; head = next; }

        else { dropped++; }

        HAL_UART_Receive_IT(&huart2, &rx_byte, 1);

    }

}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)

{

    if (huart->Instance == USART2) {

        __HAL_UART_CLEAR_PEFLAG(huart);

        HAL_UART_AbortReceive(huart);

        HAL_UART_Receive_IT(&huart2, &rx_byte, 1);

    }

}

回调里没有 HAL_Delay、没有 printf，所以执行很短。缓冲区满时只增加 dropped，不会覆盖旧数据。

  }

  HAL_Delay(1);

  /* USER CODE END 3 */

# **5 配置 HC-05：AT 模式与参数**

AT 模式是模块的配置模式：上电前把 KEY/EN 接 3.3V，模块进入配置状态，你用串口助手发 AT 指令；配置完断电，把 KEY 接回 GND，再上电就恢复透传。

**表 5-1  AT 模式接线**

|   |   |   |
|---|---|---|
|**USB-TTL**|**HC-05**|**说明**|
|**5V**|VCC|标准底板接 5V；3.3V 版按丝印|
|**GND**|GND|必须共地|
|**RXD**|TXD|交叉|
|**TXD**|RXD|交叉；5V 逻辑要分压|
|**3.3V**|KEY / EN|上电前接高，进入 AT|
|**不接**|STATE|悬空|

**1.** 断电，把 USB-TTL 的 3.3V 接到 HC-05 的 KEY/EN。

**2.** 给 USB-TTL 插上电脑，HC-05 得电，LED 通常变为慢闪。

**3.** 串口助手选 USB-TTL 的 COM 口，38400、8N1、无流控，发送结尾选 CR+LF。

**4.** 发送 AT，收到 OK 说明进入 AT 模式；没有反应就依次试 9600、115200。

**5.** 按需发送下表指令，每条等 OK；最后 AT+RESET，断电，把 KEY 接回 GND。

**表 5-2  HC-05 常用 AT 指令**

|   |   |   |
|---|---|---|
|**指令**|**作用**|**说明**|
|**AT**|测试通信|返回 OK|
|**AT+NAME=STM32_BT**|改名称|手机搜索到的名字|
|**AT+PSWD="1234"**|改密码|报错时试不带引号|
|**AT+UART=9600,0,0**|设 9600 8N1|必须与 CubeMX 的 USART2 一致|
|**AT+ROLE=0**|设为从机|手机主动连接时用从机|
|**AT+CMODE=1**|允许任意地址连接|学习阶段用 1|
|**AT+UART?**|查串口参数|+UART:9600,0,0|
|**AT+NAME?**|查名称|+NAME:...|
|**AT+ADDR?**|查 MAC|主机绑定从机时用|
|**AT+ORGL**|恢复出厂|名称/密码/波特率可能全部还原|

**代码 5-1  一次典型配置**

AT+NAME=STM32_BT      -> OK

AT+PSWD="1234"        -> OK

AT+UART=9600,0,0      -> OK

# **6 手机联调：第一次无线通信**

**1.** Android 设置 → 蓝牙 → 配对新设备，找到 HC-05（或你改的名字），PIN 输入 1234；失败再试 0000。

**2.** 安装 Serial Bluetooth Terminal，打开菜单 → Devices → 选择 HC-05。

**3.** 终端发送结尾设为 CR+LF，先发 PING，收到 PONG 说明整条链路打通。

**4.** 发 LED ON / LED OFF 控制 PC13；发 STATUS 查看状态。

**5.** 断开重连一次，确认还能收发；如果 App 有本地回显，关掉它，避免把发送内容当成回复。

**代码 6-1  手机端预期结果**

PING                 -> PONG

LED ON               -> OK: LED ON

STATUS               -> LED=ON DROP=0

LED OFF              -> OK: LED OFF

HELP                 -> PING | LED ON | LED OFF | STATUS | HELP

**表 6-1  手机端常见问题**

|   |   |
|---|---|
|**现象**|**先检查**|
|**搜不到 HC-05**|模块供电、是否已被别的手机连接、Android 附近设备权限|
|**配对失败**|PIN 试 1234/0000，删除旧配对记录，模块恢复出厂|

|**连接后马上断开**|供电电流不足；换 USB 口，模块 VCC 并 100 µF 电容|

# **7 排错与验收**

按“供电 → 接线 → 模块配置 → STM32 配置 → 代码/手机”的顺序排查，每次只改一个变量。先让 USB-TTL 单独和 HC-05 通 AT，再把 STM32 加进来，最后才用手机。

**表 7-1  常见问题速查**

|   |   |   |
|---|---|---|
|**现象**|**最可能原因**|**处理**|
|**HC-05 灯不亮**|VCC/GND 接错、供电不足|测电压，换线，单独 5V 供电|
|**灯亮但搜不到**|AT 模式、已被占用、天线遮挡|断电重启，KEY 接 GND，关闭其他连接|
|**AT 没返回**|KEY 没拉高、波特率错、TX/RX 反、没发 CRLF|按第 5 章重来，试 38400/9600/115200|
|**AT 返回 ERROR**|指令拼写、固件差异、引号|对照表 5-2，密码先带引号再不带|
|**手机发 PING 没回复**|USART2 接线/波特率/中断/代码|看 USART1 日志，打断点看回调|
|**回复乱码**|两端波特率不一致|CubeMX 和模块统一 9600|
|**只能收不能发**|模块 RXD 没接、代码没调用发送|检查 PA2→RXD，测 PA2 波形|
|**只能发不能收**|模块 TXD 没接、NVIC 没开|检查 PA3←TXD，勾选 USART2 中断|
|**收一次就死机**|回调没重新启动接收、中断里阻塞|回调末尾重新 Receive_IT，去掉延时|
|**数据一多就丢**|主循环太慢、缓冲区小|减少延时，增大缓冲，改 DMA|
|**重新上电连不上**|手机保留旧连接、模块没复位|取消配对，模块断电重启|
|**ST-Link 下载失败**|SWD 接线、BOOT0、芯片被锁|检查接线，BOOT0=0，Connect under Reset|
|**编译找不到 arm-none-eabi-gcc**|工具链 bundle 未安装|重新选择 bundle，或安装 CMake/Ninja/GCC|
|**串口无日志**|PA9/PA10 接错、_write 没实现|检查交叉和 115200|
|**重新生成代码后代码没了**|写在 USER CODE 外面|把代码移进 USER CODE 区域|
